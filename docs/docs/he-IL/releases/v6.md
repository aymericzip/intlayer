# Intlayer v6 החדש - מה חדש?

ברוכים הבאים ל-Intlayer v6! גרסה זו מתמקדת בביצועים, חוויית מפתח ואמינות. להלן עיקרי הדברים, כולל הערות הגירה ודוגמאות מוכנות להעתקה והדבקה.

## עיקרי הגרסה

- פקודה חדשה: `npx intlayer content test` לאיתור תרגומים חסרים
- אפשרות גלובלית חדשה `autoFill` ליצירה אוטומטית של תרגומים חסרים
- פקודת ה-fill מדלגת כעת כברירת מחדל על תרגומים קיימים: `npx intlayer fill`
- הרחבה ל-VS Code: שורת פעילות (Activity Bar) חדשה של Intlayer (חיפוש ומילונים), פעולות בסרגל הכלים ובתפריט ההקשר, חשיפה אוטומטית (auto-reveal), ופקודות Fill/Test
- בנייה מהירה פי 10 הודות להרצת promises במקביל
- שמירה במטמון (caching) של מילונים מרוחקים כדי למנוע אחזור מחדש בעת הפעלת האפליקציה
- רישום לוגים משופר: הגדירו `log.mode: 'verbose'` כדי לבחון את ההתנהגות
- אימות (validation) חזק יותר למניעת קריסות אפליקציה עקב בעיות במילונים
- עדכונים חיים עם ה-CMS באמצעות `build.importMode = 'live'` ו-`pnpm intlayer live`
- תיקונים: אינטגרציה עם Vue.js, מתאם Lynx, והעורך החזותי (Visual Editor) ב-Windows

## חדש: autoFill גלובלי להשלמת תרגומים חסרים

כעת ניתן להפעיל מילוי אוטומטי (auto-fill) באופן גלובלי, כך שכל מילון עם תרגומים חסרים יושלם אוטומטית.

```ts fileName="intlayer.config.ts"
import { type IntlayerConfig, Locales } from "intlayer";

const config: IntlayerConfig = {
  internationalization: {
    locales: [Locales.ENGLISH, Locales.FRENCH, Locales.SPANISH],
    defaultLocale: Locales.ENGLISH,
    requiredLocales: [Locales.ENGLISH, Locales.FRENCH],
  },
  content: {
    // יצירה אוטומטית של תרגומים חסרים עבור כל המילונים
    autoFill: "./{{fileName}}Filled.content.ts",
    //
    // autoFill: "/messages/{{locale}}/{{key}}/{{fileName}}.content.json",
    //
    // autoFill: true, // יצירה אוטומטית של תרגומים חסרים עבור כל המילונים כמו שימוש ב-"./{{fileName}}.content.json"
    //
    // autoFill: {
    //   en: "./{{fileName}}.en.content.json",
    //   fr: "./{{fileName}}.fr.content.json",
    //   es: "./{{fileName}}.es.content.json",
    // },
  },
};

export default config;
```

מלאו אוטומטית את התרגומים החסרים באמצעות הפקודה `npx intlayer fill`.

עדיין ניתן להגדיר זאת ברמת דיוק גבוהה לכל מילון בנפרד באמצעות השדה `autoFill` בקובצי התוכן. Intlayer תתחשב תחילה בהגדרה הספציפית של המילון ותחזור להגדרה הגלובלית במידת הצורך. עיינו במדריך המלא ב-[מילוי אוטומטי (Auto-fill)](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/autoFill.md) וב-[מדריך קובצי תוכן](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/dictionary/content_file.md).

- [מילוי אוטומטי (Auto-fill)](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/autoFill.md)
- [מדריך קובצי תוכן](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/dictionary/content_file.md)

## הרחבה מעודכנת ל-VS Code

ההרחבה כוללת כעת לשונית ייעודית של Intlayer בשורת הפעילות (Activity Bar) ומספר שיפורים בתהליך העבודה:

- שורת פעילות של Intlayer עם שתי תצוגות:
  - תצוגת אינטרנט (Search webview) לחיפוש חי של מילונים ותוכן
  - עץ מילונים המפרט סביבות, מילונים וקבצים תורמים
- סרגל כלים בתצוגת המילונים: Build, Pull, Push, Fill, Refresh, Test, Create Dictionary File
- תפריטי הקשר: Pull/Push במילונים; Fill בקבצים
- חשיפה אוטומטית (Auto-reveal): הקובץ הפעיל בעורך מודגש בעץ המילונים בעת הצורך
- פקודות חדשות הזמינות מלוח הפקודות (Command Palette): Fill Dictionaries ו-Test Dictionaries

ראו פרטים נוספים בתיעוד [הרחבת VS Code הרשמית](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/vs_code_extension.md).

- [הרחבת VS Code הרשמית](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/vs_code_extension.md)

שרת ה-MCP עודכן לתמיכה בתכונות החדשות.

- מילוי אוטומטי (Auto-fill)
- בדיקת תרגומים חסרים
- עדכונים חיים
- רישום לוגים (Logging)
- אימות (Validation)
- הערות הגירה
- תיעוד

> שרת ה-MCP מסייע באוטומציה של פרויקטים המשתמשים ב-Intlayer. בדיקת תרגומים חסרים עבור קוד שנוצר אוטומטית. הוא מסייע בהבנת התצורה שלכם, ומטמיע את התיעוד של Intlayer ישירות ב-IDE שלכם.

## שיפורים ברישום לוגים

};

## אימות חזק יותר

עיבוד המילונים מבצע כעת אימות חזק יותר. כאשר מילון נכשל בעיבוד, Intlayer מונעת את קריסת האפליקציה שלכם ומציגה שגיאות ברורות לפעולה.

## עדכונים חיים עם CMS (בטוח לייצור)

הגישו עדכוני תוכן חיים (למשל, עדכוני עריכה) בסביבת ייצור מבלי לבנות מחדש את האפליקציה שלכם.

1. הפעילו מצב ייבוא חי (live import mode):

```ts fileName="intlayer.config.ts"
import { type IntlayerConfig } from "intlayer";

const config: IntlayerConfig = {
  build: {
    importMode: "live", // "static" | "dynamic" | "live"
  },
  editor: {
    liveSync: true, // הפעלת סנכרון חי בצד השרת
  },
};

export default config;
```

2. הריצו את האפליקציה ואת תהליך ה-live זה לצד זה:

```bash packageManager="npm"
npx intlayer live --with 'vite preview'
```

```bash packageManager="yarn"
yarn intlayer live --with 'vite preview'
```

```bash packageManager="pnpm"
pnpm intlayer live --with 'vite preview'
```

```bash packageManager="bun"
bun x intlayer live --with 'vite preview'
```

הערות:

- רק מילונים שסומנו לשימוש במצב live ייאחזרו בזמן אמת. מילונים אחרים ממוטבים לביצועים.
- מעבר אוטומטי לייבוא דינמי אם ה-API החי אינו זמין.

ראו [CMS וסנכרון חי (Live Sync)](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/intlayer_CMS.md) ו-[הגדרה (Configuration)](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/configuration.md) להנחיות מלאות.

- [CMS וסנכרון חי (Live Sync)](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/intlayer_CMS.md)

## תהליך מקבילי למעקב אחר קבצים ב-Turbopack

בעת שימוש ב-Turbopack ב-Next.js 14 ומעלה כשרת הפיתוח שלכם עם הפקודה `next dev --turbopack`, שינויים במילונים לא יזוהו אוטומטית כברירת מחדל.

מגבלה זו מתרחשת מכיוון ש-Turbopack אינו יכול להריץ תוספי webpack במקביל כדי לעקוב אחר שינויים בקובצי התוכן שלכם.

כדי לעקוף זאת, הסרנו את הפקודה `intlayer watch`, והוספנו את האפשרות `--with` להרצת שרת הפיתוח ומעקב הבנייה של Intlayer בו-זמנית.

```json5 fileName="package.json"
{
  "scripts": {
    "dev": "npx intlayer watch --with 'next dev --turbopack'",
  },
}
```

## הערות הגירה

- הוסר: `dictionaryOutput` (בעבר `i18next` או `next-intl`). תכונה זו תחזור כמתאמים מודולריים בגרסאות עתידיות. הסירו את השדה מהתצורה שלכם.
- הסרה קשורה: `i18nextResourcesDir` (ראו יומן שינויים ב-`doc/configuration`).
- מומלץ להשתמש באפשרות הגלובלית החדשה `content.autoFill` ליצירת תרגומים חסרים בהיקף נרחב.
- השתמשו ב-`npx intlayer content test` כדי לחסום PRs כאשר קיימים תרגומים חסרים.
- לאבחון מפורט, הגדירו `log.mode = 'verbose'`.
- השתמשו ב-`intlayer` במקום ב-`intlayerPlugin` וב-`intlayerProxy` במקום ב-`intlayerProxyPlugin` בתצורת ה-Vite שלכם.
