# Intlayer v7 החדש - מה חדש?

ברוכים הבאים ל-Intlayer v7! גרסה מרכזית זו מציגה שיפורים משמעותיים בביצועים, בבטיחות טיפוסים ובחוויית המפתח. להלן עיקרי הדברים, כולל הערות הגירה ודוגמאות מעשיות.

## עיקרי הגרסה

- תמיכה ב-Next.js 16
- אסטרטגיית שמירה במטמון (caching) לבניות מהירות יותר
- יצירת טיפוסי TypeScript משופרת עם טיפוסים ספציפיים לכל שפה (locale)
- אופטימיזציית חבילה (Bundle optimization): שפות כמחרוזות במקום enum
- מצבי ניתוב חדשים: `prefix-no-default`, `prefix-all`, `no-prefix`, `search-params`
- תאימות ל-GDPR באמצעות localStorage
- תצורת אחסון גמישה: עוגיות (cookies), `localStorage`, `sessionStorage` או שילוב ביניהם
- הקטנת גודל החבילה של העורך החזותי (Visual Editor) ב-30%
- אפשרויות תצורה משופרות עבור ה-middleware
- התנהגות מעודכנת של פקודת fill לניהול תוכן טוב יותר
- מקטע תצורת מילון חדש לארגון טוב יותר
- יציבות משופרת עם עדכונים מלאים של קובצי הצהרת תוכן
- ניהול ניסיונות חוזרים חכם (Intelligent retry management) לדיוק התרגום
- מקבול (Parallelization) לעיבוד תרגומים מהיר יותר
- פיצול חכם למקטעים (Smart chunking) לטיפול בקבצים גדולים במגבלות ההקשר של מודלי AI
- עיצוב קוד אוטומטי עם `formatCommand` הניתן להגדרה

## ביצועים: מטמון לבניות מהירות יותר

במקום לבנות מחדש הצהרות תוכן עם esbuild בכל בנייה, v7 מיישמת אסטרטגיית מטמון המאיצה את תהליך הבנייה.

```bash packageManager="npm"
npx intlayer build
```

```bash packageManager="yarn"
yarn intlayer build
```

```bash packageManager="pnpm"
pnpm intlayer build
```

```bash packageManager="bun"
bun x intlayer build
```

מערכת המטמון החדשה:

- שומרת הצהרות תוכן מקומפלות כדי למנוע עיבוד מיותר
- מזהה שינויים ובונה מחדש רק קבצים ששונו
- מקצרת משמעותית את זמני הבנייה עבור פרויקטים גדולים

## TypeScript: יצירת טיפוסים ספציפיים לכל שפה

טיפוסי TypeScript מיוצרים כעת לכל שפה בנפרד, מה שמספק בדיקת טיפוסים חזקה יותר ומבטל טיפוסי איחוד (union types) בין כל השפות.

**התנהגות v6:**

```tsx
const content = getIntlayer("my-title-content", "en");
// typeof content = { title: "My title" } | { title: "Mon titre" } | { title: "Mi título" }
```

**התנהגות v7:**

```tsx
const content = getIntlayer("my-title-content", "en");
// typeof content = { title: "My title" }
```

יתרונות:

- השלמה אוטומטית מדויקת יותר ב-IDE שלכם
- בטיחות טיפוסים טובה יותר ללא זיהום טיפוסים בין שפות
- שיפור בביצועים על ידי הפחתת מורכבות הטיפוסים

## אופטימיזציית חבילה: שפות כמחרוזות

הטיפוס `Locales` אינו עוד enum, מה שאומר שהוא כעת ניתן לניעור עצים מלא (fully tree-shakeable) ולא ינפח את החבילה שלכם באלפי רשומות שפה שאינן בשימוש.

**v6:**

```typescript
import { Locales } from "intlayer";
// Enum הכולל את כל השפות -> אינו ניתן ל-tree-shaking מלא

const locale: Locales = Locales.ENGLISH;
```

**v7:**

```typescript
import { Locales, Locale } from "intlayer";
// טיפוס מחרוזת -> ניתן לחלוטין ל-tree-shaking

const locale: Locale = Locales.ENGLISH;
```

> מכיוון ש-`Locales` אינו עוד enum, תצטרכו לשנות את הטיפוס מ-`Locales` ל-`Locale` כדי לקבל את השפה כטיפוס.

ראו את [פרטי המימוש](https://github.com/aymericzip/intlayer/blob/main/packages/%40intlayer/types/src/index.ts) למידע נוסף.

## מצבי ניתוב חדשים לגמישות מרבית

v7 מציגה תצורת `routing.mode` אחידה המחליפה את האפשרויות הקודמות `prefixDefault` ו-`noPrefix`, ומציעה שליטה מדויקת יותר על מבנה ה-URL.

### מצבי ניתוב זמינים

- **`prefix-no-default`** (ברירת מחדל): לשפת ברירת המחדל אין קידומת, לשפות אחרות יש
  - `/dashboard` (en) או `/fr/dashboard` (fr)
- **`prefix-all`**: לכל השפות יש קידומת
  - `/en/dashboard` (en) או `/fr/dashboard` (fr)
- **`no-prefix`**: אין קידומות שפה בכתובות ה-URL (השפה מטופלת באמצעות אחסון/כותרות)
  - `/dashboard` עבור כל השפות
- **`search-params`**: השפה מועברת כפרמטר שאילתה (query parameter)
  - `/dashboard?locale=en` או `/dashboard?locale=fr`

### תצורה בסיסית

```typescript
// intlayer.config.ts
export default {
  internationalization: {
    locales: ["en", "fr", "es"],
    defaultLocale: "en",
  },
  routing: {
    mode: "prefix-no-default", // ברירת מחדל
  },
};
```

## תאימות ל-GDPR: אחסון ב-localStorage / עוגיות

v7 מתעדפת את פרטיות המשתמש על ידי שימוש ב-`localStorage` כמנגנון האחסון המוגדר כברירת מחדל במקום עוגיות (cookies). שינוי זה מסייע בתאימות ל-GDPR על ידי הימנעות מדרישות להסכמת עוגיות עבור העדפות שפה.

### אפשרויות תצורת אחסון

השדה החדש `routing.storage` זמין גם בנוסף לאפשרויות הקודמות `middleware.cookieName` ו-`middleware.serverSetCookie`, ומציע תצורות אחסון גמישות:

```typescript
// השבתת אחסון
storage: false

// סוגי אחסון פשוטים
storage: 'cookie'
storage: 'localStorage'
storage: 'sessionStorage'

// עוגייה עם מאפיינים מותאמים אישית
storage: {
  type: 'cookie',
  name: 'custom-locale',
  domain: '.example.com',
  secure: true,
  sameSite: 'strict'
}

// localStorage עם מפתח מותאם אישית
storage: {
  type: 'localStorage',
  name: 'custom-locale'
}

// מספר סוגי אחסון ליתירות
storage: ['cookie', 'localStorage']
```

### דוגמה לתצורה תואמת GDPR

עבור יישומי ייצור שצריכים לאזן בין פונקציונליות לבין תאימות ל-GDPR:

```typescript fileName="intlayer.config.ts"
export default {
  internationalization: {
    locales: ["en", "fr", "es"],
    defaultLocale: "en",
  },
  routing: {
    mode: "prefix-no-default",
    storage: [
      {
        type: "localStorage", // אחסון ראשי (אינו דורש הסכמה)
        name: "user-locale",
      },
      {
        type: "cookie", // אחסון עוגיות אופציונלי (דורש הסכמה)
        name: "user-locale",
        secure: true,
        sameSite: "strict",
        httpOnly: false,
      },
    ],
  },
};
```

### הפעלת / השבתת אחסון עוגיות

דוגמה באמצעות React / Next.js:

ניתן להגדרה גלובלית:

```typescript
<IntlayerProvider isCookieEnabled={false}>
  <App />
</IntlayerProvider>
```

ניתן לעקוף מקומית עבור כל hook:

```ts
const { setLocale } = useLocale({ isCookieEnabled: false });

setLocale("en");
```

**הערה:** עוגיות מופעלות כברירת מחדל.
**הערה:** בדקו את [דרישות עוגיות GDPR](https://gdpr.eu/cookies/) עבור מקרה השימוש הספציפי שלכם.

## העורך החזותי: חבילה קטנה ב-30%

חבילת העורך החזותי (Visual Editor) מותאמה כך שהיא קטנה ב-30% בהשוואה לגרסה הקודמת, הודות ל:

- שיפורי ביצועים בעורך הקוד
- הסרת תלויות מיותרות בחבילות הליבה של Intlayer
- tree-shaking ואריזת מודולים משופרת

הדבר מביא לזמני הורדה מהירים יותר ולביצועי ריצה משופרים עבור האפליקציה שלכם.

## עיצוב קוד אוטומטי: תצורת formatCommand

v7 מציגה את האפשרות `formatCommand` בתצורת העורך, המאפשרת לעצב אוטומטית קובצי תוכן כאשר הם נכתבים על ידי Intlayer. הדבר מבטיח סגנון קוד ועיצוב עקביים בכל קובצי הצהרת התוכן שלכם.

אם לא הוגדר, Intlayer תנסה לזהות את פקודת העיצוב באופן אוטומטי, על ידי ניסיון לזהות את הפקודות הבאות: prettier, biome, eslint.

### תצורה

האפשרות `formatCommand` מקבלת תבנית מחרוזת שבה `{{file}}` יוחלף בנתיב הקובץ בפועל:

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    formatCommand: 'bun x biome format "{{file}}" --write --log-level none',
  },
};
```

### מעצבי קוד נתמכים

ניתן להשתמש בכל מעצב קוד (formatter) שמקבל נתיבי קבצים כארגומנטים:

**שימוש ב-Biome:**

```typescript
formatCommand: 'bun x biome format "{{file}}" --write --log-level none';
```

**שימוש ב-Prettier:**

```typescript
formatCommand: 'npx prettier --write "{{file}}" --log-level silent';
```

**שימוש ב-ESLint:**

```typescript
formatCommand: 'npx eslint --fix "{{file}}" --quiet';
```

**שימוש במעצב המובנה של Bun:**

```typescript
formatCommand: 'bun format "{{file}}"';
```

### יתרונות

- **עיצוב עקבי**: כל קובצי התוכן מעוצבים אוטומטית בהתאם להנחיות הסגנון של הפרויקט שלכם
- **חוויית מפתח**: אין צורך לעצב קבצים ידנית לאחר ש-Intlayer כותבת אותם
- **עקביות בצוות**: מבטיח שכל חברי הצוות עובדים עם אותו עיצוב המוחל על קובצי התוכן
- **אינטגרציה עם CI/CD**: קובצי תוכן שומרים על עיצוב עקבי בתהליכי עבודה אוטומטיים

### כיצד זה עובד

כאשר Intlayer כותבת או מעדכנת קובץ הצהרת תוכן (`.content.ts`, `.content.js` וכו'), היא מריצה אוטומטית את פקודת העיצוב שצוינה על הקובץ. שומר המקום `{{file}}` מוחלף בנתיב הקובץ בפועל, והפקודה מופעלת בספריית הבסיס של הפרויקט.

## תצורת מילון: ארגון ומבנה טובים יותר

v7 מציגה מקטע תצורה ייעודי חדש בשם `dictionary` המספק ארגון טוב יותר עבור הגדרות הקשורות למילונים וניהול תוכן משופר.

### מבנה תצורת מילון חדש

המאפיין `fill` הועבר ממקטע ה-`content` למקטע `dictionary` חדש, ומספק הפרדה ברורה יותר של תחומי אחריות:

**תצורת v6:**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    autoFill: "./{{fileName}}.content.json",
    contentDir: ["src"],
  },
};
```

**תצורת v7:**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    contentDir: ["src"],
  },
  dictionary: {
    fill: "./{{fileName}}.content.json",
  },
};
```

### יתרונות המבנה החדש

- **ארגון ברור יותר**: הגדרות ספציפיות למילון מקובצות כעת יחד
- **הפרדה טובה יותר של תחומי אחריות**: גילוי תוכן לעומת פעולות מילון מופרדים כעת בבירור
- **תחזוקתיות משופרת**: קל יותר להבין ולשנות תצורות הקשורות למילונים
- **יכולת הרחבה עתידית**: מקטע ה-dictionary יכול להכיל הגדרות עתידיות נוספות הספציפיות למילונים
- **ניהול מילונים מקיף**: כולל מאפיינים כגון `title`, `live`, `priority`, `tags`, `version` ו-`description` ליצירה וניהול של מילונים חדשים

### שימוש בתצורה

תצורת המילון משרתת שתי מטרות עיקריות:

1. **ערכי ברירת מחדל**: הגדרת ערכי ברירת מחדל בעת יצירת קובצי הצהרת תוכן
2. **התנהגות ברירת מחדל לנסיגה (Fallback)**: מתן ערכי fallback כאשר שדות ספציפיים אינם מוגדרים, ומאפשרת להגדיר את התנהגות פעולות המילון באופן גלובלי

מקטע ה-dictionary כולל מאפיינים מקיפים לניהול מילונים:

- **`fill`**: התנהגות מילוי אוטומטי ליצירת תוכן
- **`title`**: כותרת ברירת מחדל למילונים חדשים
- **`live`**: תצורת סנכרון חי לעדכונים בזמן אמת
- **`priority`**: הגדרות עדיפות לפענוח מילונים
- **`tags`**: תגיות ברירת מחדל לארגון תוכן
- **`version`**: ניהול גרסאות עבור עדכוני מילון
- **`description`**: תיאור ברירת מחדל לתוכן חדש

למידע נוסף אודות קובצי הצהרת תוכן וכיצד ערכי התצורה מוחלים, עיינו ב-[תיעוד קובצי תוכן](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he/dictionary/content_file.md).

- [תיעוד קובצי תוכן](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he/dictionary/content_file.md)

## פקודת Fill: התנהגות מעודכנת לניהול תוכן טוב יותר

v7 מציגה התנהגות משופרת עבור הפקודה `fill`, ומספקת ניהול תוכן גמיש וצפוי יותר:

### התנהגות fill חדשה

- **`fill: true`** - כותב מחדש את הקובץ הנוכחי עם תוכן מלא עבור כל השפות
- **`fill: "path/to/file"`** - ממלא את הקובץ שצוין מבלי לשנות את הקובץ הנוכחי
- **`fill: false`** - משבית לחלוטין את המילוי האוטומטי

### תמיכה משופרת במבני תוכן מורכבים

פקודת ה-fill תומכת כעת במבני הצהרת תוכן מורכבים, כולל:

- **אובייקטים מורכבים (Composed objects)**: הצהרות תוכן המתייחסות לאובייקטים אחרים
- **תוכן מפורק (Destructured content)**: תוכן המשתמש בתבניות פירוק (destructuring)
- **הפניות מקוננות (Nested references)**: אובייקטים הקוראים זה לזה בהיררכיות מורכבות
- **מבני תוכן דינמיים (Dynamic content structures)**: תוכן עם מאפיינים מותנים או מחושבים

### יתרונות

- **כוונה ברורה יותר**: ההתנהגות כעת מפורשת יותר לגבי מה שמשתנה
- **הפרדה טובה יותר**: ניתן לשמור קובצי תוכן בנפרד מתרגומים שמולאו
- **זרימת עבודה משופרת**: למפתחים יש יותר שליטה על המקום שבו תרגומים נשמרים
- **תמיכה במבנים מורכבים**: טיפול בארכיטקטורות תוכן מתקדמות עם מספר אובייקטים מקושרים

### דוגמת שימוש

```typescript fileName="*.content.ts"
// כתיבה מחדש של הקובץ הנוכחי עם כל השפות
const content = {
  key: "example",
  fill: true, // כותב מחדש קובץ זה
  content: {
    title: "Hello World",
  },
};

// מילוי קובץ נפרד מבלי לשנות את הקובץ הנוכחי
const content = {
  key: "example",
  fill: "./translations.json", // יוצר/מעדכן את translations.json
  content: {
    title: "Hello World",
  },
};

// השבתת מילוי אוטומטי
const content = {
  key: "example",
  fill: false, // ללא מילוי אוטומטי
  content: {
    title: "Hello World",
  },
};

// מבנה תוכן מורכב עם אובייקטים מורכבים
const sharedContent = {
  buttons: {
    save: "Save",
    cancel: "Cancel",
  },
};

const content = {
  key: "complex-example",
  fill: true,
  content: {
    // הפניות לאובייקטים אחרים
    sharedContent,

    // תוכן מפורק
    ...sharedContent,

    // הפניות מקוננות
    sections: [
      {
        ...sharedContent.buttons,
        header: "Section 1",
      },
    ],
  },
};
```

## יציבות משופרת וניהול תרגום

v7 מציגה מספר שיפורים כדי להפוך את תרגום התוכן לאמין ויעיל יותר:

### עדכונים מלאים של קובצי הצהרת תוכן

המערכת מעדכנת כעת קובצי `.content.{ts,js,cjs,mjs}` במלואם במקום עדכונים חלקיים, מה שמבטיח:

- **שלמות נתונים**: כתיבה מחדש מלאה של הקובץ מונעת עדכונים חלקיים שעלולים להשחית תוכן
- **עקביות**: כל השפות מעודכנות באופן אטומי, תוך שמירה על סנכרון
- **אמינות**: מפחית את הסיכון לקובצי תוכן חלקיים או פגומים

### ניהול ניסיונות חוזרים חכם

מנגנוני ניסיון חוזר חדשים מונעים דחיפת תוכן בפורמטים שגויים, ומונעים את שבירת כל תהליך ה-fill אם בקשה אחת נכשלת.

### מקבול לעיבוד מהיר יותר

פעולות תרגום פועלות כעת בתור כדי להריץ אותן במקביל. הדבר מאיץ משמעותית את התהליך.

### פיצול חכם לקבצים גדולים

אסטרטגיות פיצול מתקדמות מטפלות בקובצי תוכן גדולים מבלי לחרוג מחלונות ההקשר של מודלי AI:

### דוגמה לתהליך עבודה

```typescript fileName="*.content.ts"
// קובץ תוכן גדול מפוצל אוטומטית למקטעים
const content = {
  key: "large-documentation",
  fill: true,
  content: {
    // תוכן גדול מפוצל אוטומטית לעיבוד AI
    introduction: "...", // 5000+ תווים
    sections: [
      // מספר מקטעים גדולים
    ],
  },
};
```

המערכת מבצעת באופן אוטומטי:

1. ניתוח גודל ומבנה התוכן
2. פיצול התוכן למקטעים בצורה מתאימה
3. עיבוד המקטעים במקביל
4. אימות וניסיון חוזר בעת הצורך
5. שחזור הקובץ השלם

## הערות הגירה מ-v6

### תצורות שהוסרו

- **`middleware.cookieName`**: הוחלף על ידי `routing.storage`
- **`middleware.serverSetCookie`**: הוחלף על ידי `routing.storage`
- **`middleware.prefixDefault`**: הוחלף על ידי `routing.mode`
- **`middleware.noPrefix`**: הוחלף על ידי `routing.mode`

### תצורות חדשות

- **`editor.formatCommand`**: אפשרות חדשה לעיצוב קוד אוטומטי של קובצי תוכן

### מיפוי הגירה

#### מיפוי תצורה

| תצורת v6                   | תצורת v7                                         |
| -------------------------- | ------------------------------------------------ |
| `content.autoFill: xxx`    | `dictionary.fill: xxx`                           |
| `prefixDefault: false`     | `mode: 'prefix-no-default'`                      |
| `prefixDefault: true`      | `mode: 'prefix-all'`                             |
| `noPrefix: true`           | `mode: 'no-prefix'`                              |
| `cookieName: 'my-locale'`  | `storage: { type: 'cookie', name: 'my-locale' }` |
| `serverSetCookie: 'never'` | `storage: false` או הסרת cookie ממערך האחסון     |

#### דוגמת הגירה

**לפני (v6):**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    autoFill: "./{{fileName}}.content.json",
    contentDir: ["src"],
  },
  middleware: {
    headerName: "x-intlayer-locale",
    cookieName: "intlayer-locale",
    prefixDefault: false,
    basePath: "",
    serverSetCookie: "always",
    noPrefix: false,
  },
};
```

**אחרי (v7):**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    contentDir: ["src"],
  },
  dictionary: {
    fill: "./{{fileName}}.content.json",
  },
  routing: {
    mode: "prefix-no-default",
    storage: "localStorage", // או 'cookie' אם נדרש אחסון בעוגיות
    headerName: "x-intlayer-locale",
    basePath: "",
  },
  editor: {
    formatCommand: 'bun x biome format "{{file}}" --write --log-level none', // אופציונלי: עיצוב אוטומטי
  },
};
```

#### מיפוי תוכן מילון

| תוכן מילון ב-v6 | תוכן מילון ב-v7 |
| --------------- | --------------- |
| `autoFill: xxx` | `fill: xxx`     |

#### דוגמת הגירה

**לפני (v6):**

```typescript fileName="*.content.ts"
const content = {
  key: "example",
  autoFill: true, // כותב מחדש קובץ זה
  content: {
    title: "Hello World",
  },
};
```

**אחרי (v7):**

```typescript fileName="*.content.ts"
const content = {
  key: "example",
  fill: true, // כותב מחדש קובץ זה
  content: {
    title: "Hello World",
  },
};
```
