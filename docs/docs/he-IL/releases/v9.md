# Intlayer v9 החדש - מה חדש?

ברוכים הבאים ל-Intlayer v9! גרסה מרכזית זו מהווה אבן דרך עצומה בפישוט תהליך ההגירה ל-Intlayer עם **חבילות מתאם תאימות (Compat Adapter Packages)** עבור ספריות ה-i18n המובילות (`react-i18next`, `next-intl`, `vue-i18n` ועוד), מוסיפה תמיכה במבני תוכן עשירים (**Collections** ו-**Variants**), ומציגה את **`@intlayer/analytics`** למעקב אחר חשיפת תוכן והרצת בדיקות A/B.

## חבילות מתאם תאימות

ההגירה ל-Intlayer מספריות i18n פופולריות קלה כעת מאי פעם. יצרנו חמש חבילות תאימות החושפות את **אותם ממשקי API ציבוריים בדיוק** כמו ספריות ה-i18n הסטנדרטיות, אך מאצילות את כל עבודת התרגום ל-Intlayer בזמן ריצה.

### חשיפת אותו API ציבורי עם טיפוסים קפדניים

על ידי החלפת ייבוא (imports), אתם מקבלים את כל היתרונות של Intlayer (כולל בטיחות טיפוסים בזמן הידור מול המילונים בפועל) עם שינויי קוד מינימליים:

- `@intlayer/i18next`
- `@intlayer/react-i18next`
- `@intlayer/next-intl`
- `@intlayer/react-intl`
- `@intlayer/next-i18next`
- `@intlayer/vue-i18n`
- `@intlayer/lingui`

לדוגמה, פשוט שנו מ:

```ts
import { useTranslation } from "react-i18next";
```

ל:

```ts
import { useTranslation } from "@intlayer/react-i18next";
```

המפתחות שלכם יהיו כעת **בעלי טיפוסים קפדניים** מול מילוני ה-Intlayer שלכם, ויציעו השלמה אוטומטית מלאה של נתיבי dot-path ב-IDE שלכם!

### תוספי כינויים למארזים (Vite, Next.js, Turbopack)

כדי לאפשר הגירה מבלי לשכתב ידנית את כל הצהרות הייבוא שלכם, כל חבילת מתאם תאימות כוללת **תוסף מארז מותאם אישית** (Vite או Next.js) תחת תת-הנתיב `/plugin`.

תוספים אלה משכתבים אוטומטית ייבוא קיים (למשל `react-i18next` או `next-intl`) למקביליהם ב-`@intlayer/*` בזמן הבנייה.

#### דוגמת Next.js (Webpack / Turbopack)

במקום `withIntlayer`, עטפו את תצורת ה-Next.js שלכם באמצעות תוסף התאימות:

```ts fileName="next.config.ts"
import { createNextI18nPlugin } from "@intlayer/next-i18next/plugin";
import type { NextConfig } from "next";

const withIntlayer = createNextI18nPlugin();
const nextConfig: NextConfig = {};

export default withIntlayer(nextConfig);
```

#### דוגמת Vite (React, Vue, Solid, Svelte)

```ts fileName="vite.config.ts"
import vueI18nVitePlugin from "@intlayer/vue-i18n/plugin";

export default defineConfig({
  plugins: [vueI18nVitePlugin()],
});
```

## מפענח זמן ריצה משותף

כל מתאמי התאימות מנתבים כעת את פענוח התרגום דרך מנתח יחיד וממוטב ביותר בזמן ריצה: `@intlayer/core/messageFormat`.

- **Interpolate Message**: מפענח תבניות סטנדרטיות `{{var}}` (רווחים ונתיבי נקודות), ארגומנטים מעוצבים לפי ICU (`{v, number, percent}` וכו'), ותבניות `{var}` פשוטות.
- **Message Node Resolver**: מפענח צמתים מקוננים: `insert()`, `plural()` (כללי ריבוי של CLDR), `enu()` (ספירה/אנומרציה), `gender()`, תגיות HTML, מערכים וצומתי פונקציות הניתנים לקריאה.
- **Tokenized Tag Parser**: תומך בתגיות XML/HTML מוטבעות ובתגיות ממוספרות (למשל, `<1>children</1>`) כדי לאפשר רינדור טקסט עשיר מהקופסה.

## מפרט תכונה: אוספים וגרסאות

Intlayer v9 מתרחבת מעבר לאובייקטי מפתח-ערך סטטיים, ומאפשרת למילונים להצהיר על מבני פריסה דינמיים המוגדרים טיפוסית מקצה לקצה.

### 1. אוספים

הגדירו רשימה מנוהלת CMS של פריטים מסודרים (למשל שאלות נפוצות, מוצרים או רשימות בלוג). כל פריט שוכן בקובץ `.content.ts` משלו עם אותו `key` ומספר `item`:

```ts fileName="faq.1.content.ts"
import { t, type Dictionary } from "intlayer";

export default {
  key: "faq",
  item: 1,
  content: {
    question: t({ en: "What is Intlayer?", fr: "Qu'est-ce qu'Intlayer ?" }),
    answer: t({ en: "An i18n toolkit.", fr: "Une boîte à outils i18n." }),
  },
} satisfies Dictionary;
```

```ts fileName="faq.2.content.ts"
import { t, type Dictionary } from "intlayer";

export default {
  key: "faq",
  item: 2,
  content: {
    question: t({ en: "Is it free?", fr: "Est-ce gratuit ?" }),
    answer: t({ en: "Yes, open-source.", fr: "Oui, open-source." }),
  },
} satisfies Dictionary;
```

#### שימוש:

```ts
// שליפת כל הפריטים כמערך
const allFaqs = useIntlayer("faq"); // -> { question: string, answer: string }[]

// שליפת פריט בודד לפי אינדקס
const faq = useIntlayer("faq", { item: 2 }); // -> { question: string, answer: string }
```

### 2. גרסאות

הגישו בדיקות A/B, כותרות עונתיות, דגלי תכונות (feature flags) או דפי נחיתה מותאמים אישית:

#### גרסאות מחרוזת (למשל בדיקות A/B)

```ts fileName="hero.content.ts"
import { t, type Dictionary } from "intlayer";

export default {
  key: "hero-banner",
  variant: "default",
  content: {
    control: t({ en: "Welcome", fr: "Bienvenue" }),
    black_friday: t({ en: "Shop now", fr: "Acheter maintenant" }),
  },
} satisfies Dictionary;
```

#### שימוש:

```ts
const banner = useIntlayer("hero-banner", { variant: "black_friday" });
```

#### גרסאות אובייקט (למשל רשומות דינמיות)

```ts fileName="product.content.ts"
import { t, type Dictionary } from "intlayer";

export default {
  key: "product-copy",
  variant: {
    id: "prod_123",
    category: "books",
  },
  content: {
    title: t({ en: "Clean Code", fr: "Code Propre" }),
  },
} satisfies Dictionary;
```

#### שימוש:

```ts
// שליפת הרשומה המבוקשת בלבד באופן דינמי (דורש Suspense)
const product = useIntlayer("product-copy", {
  variant: { id: "prod_123", category: "books" },
});
```

## `@intlayer/analytics`: מעקב חשיפת תוכן ובדיקות A/B

חבילה אופציונלית חדשה, [`@intlayer/analytics`](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/analytics.md), מציגה לכם איזה תוכן מוצג בפועל למבקרים שלכם, ומשלימה את המעגל של **Collections ו-Variants** על ידי מתן אפשרות לבצע בדיקות A/B על תוכן ולמדוד המרות לכל גרסה.

- **מעקב ברמת ה-Provider**: ה-`IntlayerProvider` (ב-React / Next.js / React Native) מתעד אוטומטית אירועי `page_view` בטעינה, בשינוי נתיב ובשינוי שפה.
- **מעקב ברמת ה-Node**: כל פענוח של `useIntlayer` מדווח על אירוע `content_exposure`, כולל מפתח המילון, נתיב המפתח, השפה, ו-(כאשר רלוונטי) ה-**variant** של בדיקת ה-A/B שהוצגה. חשיפות חוזרות בתוך חלון שטיפה מאוחדות יחד.
- **הקצאת A/B דטרמיניסטית**: הפונקציה `getVariant(experimentKey, variants)` מקצה כל סשן לגרסה **ללא פנייה לשרת**, כך שאין הבהוב לפני הרינדור הראשון.
- **`useConversion()`**: שייכו יעד (הרשמה, לחיצה, רכישה...) לגרסה שאליה נחשף הסשן.
- **ללא עלות כאשר אינו מותקן**: אותו דפוס tree-shakeable כמו ב-`@intlayer/editor`, ייבוא דינמי `import()` עטוף ב-`try/catch`, בתוספת משתנה סביבה בזמן הידור (`INTLAYER_ANALYTICS_ENABLED`) שמסיר לחלוטין את כל האינטגרציה מקוד האפליקציה עבור אפליקציות שלא בחרו להפעיל זאת.
- **ללא סכמת תצורה חדשה**: עושה שימוש חוזר ב-`editor.backendURL` (נקודת קצה לקליטה / אירוח עצמי) וב-`editor.clientId` (מפתח פרויקט, המשמש גם כמתג הפעלה).
- **כיבוד פרטיות**: גיבוב אנונימי של סשנים (SHA-256, ללא שמירת מזהים גולמיים), ללא שמירת כתובות IP, מיקום גיאוגרפי גס ברמת מדינה בלבד, ובקשות מקובצות בערך כל 20 שניות.
- **לוח בקרה (Dashboard)**: דף **אנליטיקה** חדש (מוצג בסרגל הצד לאחר בחירת פרויקט) מדווח על משתמשים פעילים, משתמשים היום, משתמשים ב-7/30/90 הימים האחרונים, גרף התפתחות מבקרים, ופילוח שפות לעומת מיקומים.

```tsx fileName="CTAButton.tsx" codeFormat="tsx"
import { useConversion } from "react-intlayer";

const CTAButton = () => {
  const trackConversion = useConversion();

  return (
    <button
      onClick={() =>
        trackConversion({
          experimentKey: "homepage-hero",
          variant: "black_friday",
          goal: "cta_click",
        })
      }
    >
      Get started
    </button>
  );
};
```

```bash packageManager="npm"
npm install @intlayer/analytics
```

זמין כיום עבור React, Next.js ו-React Native (באמצעות `react-intlayer`); קישורים לשאר ה-frameworks (כגון Vue, Svelte, Angular...) מתוכננים בהתאם לאותו דפוס השקה של `@intlayer/editor`. עיינו ב-[תיעוד האנליטיקה](https://github.com/aymericzip/intlayer/blob/main/docs/docs/he-IL/analytics.md) למדריך המלא.

## תוסף Vite: קומפיילר ופרוקסי מובנים

תוסף ה-Vite של `intlayer()` מאגד כעת את ה-**קומפיילר** ואת ה-**פרוקסי לניתוב שפות** ישירות, כך שרוב הפרויקטים זקוקים לתוסף יחיד בלבד ב-`vite.config.ts`:

```ts fileName="vite.config.ts"
import { defineConfig } from "vite";
import { intlayer } from "vite-intlayer";

export default defineConfig({
  plugins: [intlayer()],
});
```

- **קומפיילר**: מופעל אוטומטית כאשר `compiler.enabled` מוגדר ל-`true` ונתיב `compiler.output` מוגדר. אין צורך עוד לרשום את `intlayerCompiler()` בנפרד.
- **פרוקסי**: מופעל אוטומטית בהתבסס על האפשרות החדשה `routing.enableProxy` (`true` כברירת מחדל). הוא מחבר את ה-middleware לזיהוי שפה / הפניה / שכתוב בפיתוח, תצוגה מקדימה ו-SSR בייצור. אין צורך עוד לרשום את `intlayerProxy()` בנפרד.

### האפשרות `routing.enableProxy`

אפשרות חדשה בשם `routing.enableProxy` שולטת בשאלה האם הפרוקסי לניתוב שפות מחובר. ברירת המחדל היא `true`. השביתו אותה כאשר ברצונכם לנהל את ניתוב השפות בעצמכם:

```ts fileName="intlayer.config.ts"
import type { IntlayerConfig } from "intlayer";

const config: IntlayerConfig = {
  routing: {
    enableProxy: false, // ברירת מחדל: true
  },
};

export default config;
```

התוספים העצמאיים `intlayerCompiler()` ו-`intlayerProxy()` נותרו מיוצאים עבור הגדרות מתקדמות. רישומם לצד `intlayer()` הוא בטוח לחלוטין. כל תוסף מסיר כפילויות של עצמו ורץ פעם אחת בלבד.

## קומפיילר מושבת כברירת מחדל

החל מ-Intlayer v9, ה-**קומפיילר מושבת כברירת מחדל** (`compiler.enabled` מוגדר כעת ל-`false`). כדי להפעיל חילוץ בזמן בנייה של קובצי ה-`.content.ts` שלכם, הגדירו `compiler.enabled: true` בתצורה שלכם:

```ts fileName="intlayer.config.ts"
import type { IntlayerConfig } from "intlayer";

const config: IntlayerConfig = {
  compiler: {
    enabled: true, // ברירת מחדל: false, נדרש כדי להפעיל את הקומפיילר החל מ-v9
    output: ({ fileName }) => `./${fileName}.content.ts`,
  },
};

export default config;
```

כאשר הקומפיילר מושבת, Intlayer מדלגת על שלב החילוץ בזמן הבנייה ומסתמכת על המילונים שכבר הוצהרו. הפעילו אותו רק כאשר אתם מעוניינים שתוסף המארז (`@intlayer/swc`, `@intlayer/babel`, או תוסף ה-Vite של `intlayer()`) יחלץ תוכן באופן אוטומטי.

## React Native: ייבוא מחבילה יחידה

באפליקציית React Native או Expo, אין צורך עוד לתמרן בין `react-intlayer` לבין `react-native-intlayer`. החבילה `react-native-intlayer` כעת **מייצאת מחדש את ה-API המלא של `react-intlayer`** (hooks, כלי עזר ותת-הנתיבים `/format`, `/html` ו-`/markdown`), וה-`IntlayerProvider` שלה מחיל אוטומטית את ה-polyfills הדרושים ל-React Native.

ייבאו הכל מהחבילה היחידה `react-native-intlayer`:

```tsx
import {
  IntlayerProvider,
  useIntlayer,
  useLocale,
} from "react-native-intlayer";
```

```bash
npm install intlayer react-native-intlayer
```

> ייבוא מ-`react-intlayer` ממשיך לעבוד, אך `react-native-intlayer` היא כעת נקודת הכניסה המומלצת עבור React Native; ה-provider שלה מספק את ה-polyfills שה-provider המיועד לרשת של `react-intlayer` אינו כולל.

## CMS SDK: שימוש ב-Intlayer כמסד נתוני תוכן ללא ממשק

Intlayer v9 כוללת SDK נקי בעל אימות אוטומטי ב-`@intlayer/api` לצורך אינטראקציה תכנותית עם ה-CMS, שליפת פרויקטים, שליפת מילונים, ודחיפה או עדכון שלהם מהשרת, הסקריפטים או ה-CI שלכם. האימות (OAuth2 `client_credentials`) מנוהל ומתרענן עבורכם באופן אוטומטי.

ה-SDK מפוצל ל-**שני ייבואים נפרדים** כדי שהחבילה שלכם תכלול רק את התחומים שבהם אתם משתמשים בפועל:

1. `createIntlayerCMS`: **מאמת (authenticator)** קל משקל המחזיק באישורים ובטוקן המנוהל (ללא לקוח דומיין מצורף).
2. `dictionaryEndpoint`, `projectEndpoint`, …, **מקשרי נקודות קצה (endpoint binders)** לכל תחום, כאשר כל אחד מיובא מתת-הנתיב שלו.

```ts fileName="cms.ts"
import { createIntlayerCMS } from "@intlayer/api";
import { dictionaryEndpoint } from "@intlayer/api/dictionary";

const cms = createIntlayerCMS();

// קריאה
const { data: dictionaries } = await dictionaryEndpoint(cms).getDictionaries();

// כתיבה, שימוש ב-CMS כמסד נתונים
await dictionaryEndpoint(cms).pushDictionaries([myDictionary]);
```

> אבטחה: אישורי ה-CMS מעניקים גישת כתיבה לתוכן שלכם. צרו את המאמת רק ב-**צד השרת**, ולעולם אל תחשפו את `clientId` / `clientSecret` לדפדפן.

## אירוח עצמי

Intlayer v9 מציעה תמיכה מובנית מהשורה הראשונה בהרצת מופע Intlayer משלכם באמצעות פקודה אחת. אין צורך בחשבון Intlayer Cloud.

```sh
curl -fsSL https://intlayer.org/install.sh | sh
```

המתקין מוריד קובצי `docker-compose.yml` ו-`.env`, מייצר אוטומטית את הסודות הנדרשים, ומריץ `docker compose up -d`. הכל (לוח הבקרה, ה-API, מסד הנתונים, אחסון האובייקטים והדוא"ל הטרנזקציוני) פועל מקומית במכולות (containers).

## הערות הגירה מ-v8

אם אתם משדרגים מ-v8, שימו לב ש-v9 אינה כוללת שינויים שוברים. עם זאת, להלן השינויים המרכזיים:

- **קומפיילר מושבת כברירת מחדל**: `compiler.enabled` מוגדר כעת כברירת מחדל ל-`false`. אם אתם מסתמכים על חילוץ קובצי ה-`.content.ts` שלכם בזמן בנייה, הגדירו `compiler.enabled: true` ב-`intlayer.config.ts` שלכם.
- **תוסף Vite**: הקומפיילר והפרוקסי לניתוב שפות מאוגדים כעת בתוך `intlayer()`. אם רשמתם בעבר את `intlayerCompiler()` או `intlayerProxy()` ידנית, תוכלו להסיר אותם. כפילויות מוסרות אוטומטית, כך שהשארתם אינה מזיקה. השתמשו ב-`routing.enableProxy: false` כדי לבטל את הפרוקסי.
- **שפות ודיאלקטים (Locales & Dialects)**: בעת שימוש בתלויות i18n חיצוניות, הוסיפו את תוספי מתאם התאימות המתאימים שלהן בתצורה או בהגדרת המארז שלכם כדי לשכתב ייבוא אוטומטית.
- **בוררים מותאמים אישית (Custom Selectors)**: בעת קריאה ל-`useIntlayer`, הפרמטר השני שמור כעת לאובייקט אפשרויות המכיל `{ locale, item, variant }`. אם בעבר העברתם מחרוזת שפה ישירות, עדיין תוכלו לעשות זאת, אך השימוש באובייקט אפשרויות מומלץ לבחירות מתקדמות.
- **React Native**: החבילה `react-native-intlayer` מייצאת כעת מחדש את כל ה-API של `react-intlayer`. באפליקציית React Native, ייבאו הכל מ-`react-native-intlayer` והסירו את התלות הישירה ב-`react-intlayer`. ייבוא קיים מ-`react-intlayer` ימשיך לעבוד.
