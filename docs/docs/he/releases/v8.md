## אבולוציית תוכן עשיר: Markdown ו-HTML

Intlayer v8 מביאה שיפורים משמעותיים לאופן הטיפול בתוכן עשיר, ומציגה **צומתי HTML** (שלא היו קיימים ב-v7) ואיחוד של ה-API עם **צומתי Markdown** (שהיו קיימים ב-v7 אך שופרו).

### ה-API המאוחד `.use()`

הצגנו את המתודה `.use()` הן עבור צומתי Markdown והן עבור צומתי HTML. מתודה זו מאפשרת לכם להתאים אישית את תגיות ה-HTML או הרכיבים המשמשים במהלך הרינדור.

- **החלפת רכיבים (Component Replacement)**: תוכלו להחליף בקלות תגיות HTML או רכיבים מותאמים אישית ברכיבי ה-framework שלכם (למשל, החלפת `<a>` ב-`NextLink` או `<CustomCmp>` ברכיב React).
- **בטיחות טיפוסים (Type Safety)**: כל הפונקציות לאספקת רכיבים מוגדרות טיפוסית במלואן, מה שמבטיח שתקבלו את ה-props הנכונים.

### התנהגות רינדור כברירת מחדל

ב-v7, אם לא הוגדר ספק (provider), צומתי Markdown רונדרו כמחרוזות גולמיות, מה שחייב לעיתים קרובות ספריות חיצוניות כדי לנתח אותם.

**ב-v8, Intlayer כוללת מנתח (parser) Markdown פנימי משלה.** כברירת מחדל, צומתי Markdown מרונדרים כעת ישירות כ-HTML ללא צורך בספריות חיצוניות.

### כלי עזר חדשים לרינדור וספקים

הצגנו פונקציות ורכיבי רינדור עצמאיים חדשים כדי להעניק לכם יותר שליטה מחוץ לזרימה הסטנדרטית של `useIntlayer`.

- **Markdown**: `MarkdownRenderer`, `useMarkdownRenderer`, `renderMarkdown`. (הערה: `MarkdownProvider` היה קיים ב-v7 אך כעת משתלב עם כלים חדשים אלה).
- **HTML**: `HTMLRenderer`, `useHTMLRenderer`, `renderHTML`, `HTMLProvider`.

## קובצי תוכן ב-YAML וב-Markdown (v8.10.0)

כעת ניתן להצהיר על תוכן ישירות באמצעות סיומות הקבצים `.content.md` ו-`.content.yaml`. זהו פתרון אידיאלי עבור תוכן ארוך, בלוגים, תיעוד ומדיניות פרטיות.

קבצים אלה ניתנים לעריכה מלאה מהעורך החזותי (Visual Editor), ומספקים תהליך עבודה יעיל לחברי צוות שאינם טכניים.

## שכתוב כתובות URL מותאמות אישית

Intlayer v8 מציגה תמיכה ב-**Custom URL Rewrites**, המאפשרת להגדיר נתיבים ספציפיים לכל שפה השונים מהמבנה הסטנדרטי `/locale/path`. זוהי תכונה רבת עוצמה לשיפור SEO מקומי ומתן חוויית משתמש טבעית יותר לדוברי שפות שונות.

**שיפורים מרכזיים ב-v8:**

- **מעצבי Framework (Framework Formatters)**: פונקציות חדשות `nextjsRewrite`, `svelteKitRewrite`, `reactRouterRewrite`, `vueRouterRewrite`, `solidRouterRewrite`, `tanstackRouterRewrite`, `nuxtRewrite` ו-`viteRewrite` המספקות תחביר תבניות אידיומטי עבור כל נתב.
- **ה-Hook `useRewriteURL`**: הוק חדש בצד הלקוח המתקן בשקט את שורת הכתובת לכתובת ה-URL המקומית ה"יפה" מבלי לגרום לניווטי נתב.
- **הפניות SEO אוטומטיות (Automatic SEO Redirects)**: פרוקסי מובנה מפנה כעת אוטומטית משתמשים מנתיבים קנוניים שהוקלדו ידנית (למשל, `/fr/about`) לגרסאות המקומיות היפות יותר (למשל, `/fr/a-propos`).

**דוגמת תצורה:**

### ערכי החלפה משופרים

ב-v8, ערכי החלפה (insertions) יכולים כעת **לקבל רכיבי React (או צומתי Vue)** בנוסף למחרוזות ולמספרים. הדבר מאפשר לכם להזריק רכיבים עשירים ואינטראקטיביים ישירות לתוך תבניות ההחלפה שלכם.

Intlayer מטפלת כעת בצורה חזקה בצומתי React ו-Preact מקוננים בתוך ערכי החלפה, ומבטיחה שמבני ממשק משתמש מורכבים יישמרו וירונדרו בצורה נכונה.

**דוגמה:**

```typescript fileName="src/example.content.ts"
import { insert } from "intlayer";

export default {
  key: "my-key",
  content: {
    myInsertion: insert("Hi {{name}}"),
  },
};
```

```typescript fileName="src/openings.content.ts"
      en: plural({
        one: "{{count}} opening",
```

## אימות סכמת תוכן

Intlayer v8 מציגה אימות סכמה עבור מילונים. כעת תוכלו להגדיר סכמות אימות לשימוש חוזר בתצורה שלכם באמצעות Zod ולהחיל אותן על קובצי התוכן שלכם. הדבר מבטיח שהתוכן שלכם תמיד עומד במבנה הצפוי, ותופס שגיאות בזמן הבנייה.

```typescript fileName="src/example.content.ts"
const aboutPageMetaContent = {
  key: "about-page-meta",
```

## TypeScript: מנגנוני גישה לפרימיטיבים ב-IntlayerNode

הטיפוס `IntlayerNode` עודכן כדי לאפשר קריאה ישירה למתודות JavaScript פרימיטיביות על צומתי תוכן. הדבר מאפשר אינטראקציה ישירה עם התוכן המקומי שלכם כאילו היה מחרוזת, מספר, בוליאני או מערך פרימיטיבי רגיל.

נתמך בכל הפלטפורמות: React, Preact, Solid, Svelte, Vue ו-Angular.

### דוגמת מחרוזת

```typescript
content.placeholder; // מחזיר IntlayerNode<string>
content.placeholder.value; // מחזיר string
content.placeholder.toString(); // מחזיר string
content.placeholder.toLowerCase(); // מחזיר string
String(content.placeholder); // מחזיר string
content.placeholder.toUpperCase(); // מחזיר מחרוזת באותיות גדולות
content.placeholder.replace("a", "b"); // מחזיר מחרוזת מעודכנת
```

### זיהוי תוכן אוטומטי משופר

ב-v8, Intlayer מזהה בתבונה תחביר Markdown, תגיות HTML והחלפות משתנים במחרוזות התוכן שלכם. פירוש הדבר שלעיתים קרובות תוכלו להשמיט פונקציות עזר כמו `md()`, `html()` או `insert()`.

התנהגות זו מופעלת כברירת מחדל. כעת תוכלו לכוונן זיהוי זה באופן גלובלי ב-`intlayer.config.ts` או ברמת כל מילון בנפרד.

#### שליטה פרטנית

תוכלו להפעיל או להשבית סוגים ספציפיים של טרנספורמציות:

```typescript fileName="intlayer.config.ts"
export default {

      markdown: true,
      html: true,

  },
};
```

## אופטימיזציות בנייה ניסיוניות: Minify ו-Purge (v8.7.0)

Intlayer v8.7.0 מציגה תכונות בנייה ניסיוניות חדשות ב-`intlayer.config.ts` שלכם שנועדו למטב את חבילת הייצור שלכם:

- **צמצום מילונים (Dictionary Minification)**: מכווץ קובצי מילון כדי להקטין את גודלם.
- **ניקוי מפתחות שאינם בשימוש (Unused Key Purging)**: סורק ומסיר מפתחות תרגום שאינם בשימוש מהמילונים, ומשנה את שמם של מפתחות פעילים לתווים קצרים (למשל, `"products" -> "a"`, `"pricing" -> "b"`). הדבר מפחית את גודל החבילה בעד 5%.
- **השבתת בדיקות TypeScript**: מאיץ בניות על ידי השבתת בדיקת טיפוסי TypeScript במהלך שלב ההידור.

```typescript fileName="intlayer.config.ts"
import { Locales, type IntlayerConfig } from "intlayer";

const config: IntlayerConfig = {
  internationalization: {
    locales: [Locales.ENGLISH, Locales.FRENCH],
    defaultLocale: Locales.ENGLISH,
  },
  dictionary: {
    importMode: "dynamic",
  },
  build: {
    /**
     * כיווץ המילונים להקטנת גודל החבילה.
     */
    minify: true,

    /**
     * ניקוי מפתחות שאינם בשימוש במילונים
     */
    purge: true,

    /**
     * מציין אם תהליך הבנייה צריך לבדוק טיפוסי TypeScript
     */
    checkTypes: false,
  },
};

export default config;
```

## גמישות: מצב ייבוא מאוחד

המאפיין הבוליאני `live` הוצא משימוש לטובת המאפיין המקיף יותר `importMode`. הדבר מאפשר הגדרה מפורשת של אופן טעינת המילונים: סטטית, דינמית או באמצעות סנכרון חי.

### מצבים

- **`static`** (ברירת מחדל): המילון נארז בזמן הבנייה. מומלץ ביותר לביצועים.
- **`dynamic`**: המילון נטען בזמן ריצה (למשל, באמצעות שליפת JSON או suspense).
- **`fetch`**: המילון נשלף מה-CMS/שרת בזמן ריצה ומסונכרן.

**הגירה:**

| תצורת v7      | תצורת v8                              |
| :------------ | :------------------------------------ |
| `live: true`  | `importMode: 'fetch'`                 |
| `live: false` | `importMode: 'static'` (או 'dynamic') |

הערה: ב-Intlayer v8, המאפיין `importMode` הועבר מתצורת `build` לתצורת `dictionary` ב-`intlayer.config.ts`. הדבר מאפשר להגדיר מצב ייבוא כברירת מחדל עבור כל המילונים שלכם ועדיין להיות מסוגלים לעקוף אותו ברמת מילון בודד.

**דוגמה לתצורה גלובלית:**

```typescript fileName="intlayer.config.ts"
export default {
  dictionary: {
    importMode: "dynamic", // ברירת מחדל גלובלית
  },
  // ...
};
```

**דוגמה למילון:**

```typescript fileName="src/example.content.ts"
export default {
  key: "my-key",
  importMode: "fetch", // עוקף את התצורה הגלובלית
  content: {/* ... */},
};
```

## שליטה במיקום המילון

v8 מציגה את המאפיין `location` לניהול מפורש של המקום שבו המילונים שוכנים וכיצד הם מסתנכרנים. הדבר שימושי במיוחד עבור תהליכי עבודה היברידיים הכוללים הן קבצים מקומיים והן תוכן CMS מרוחק.

### אפשרויות

- **`local`**: המילון קיים מקומית בלבד. הוא לא יידחף ל-CMS המרוחק.
- **`remote`**: המילון מנוהל מרחוק. לאחר דחיפתו ל-CMS, הוא ינותק מהמילון המקומי. המילון המרוחק יימשך מה-CMS.
- **`local_and_remote`**: המילון קיים בשני המקומות. שינויים מקומיים נדחפים, ושינויים מרוחקים נמשכים (מסונכרנים).

**דוגמה:**

```typescript fileName="src/example.content.ts"
export default {
  key: "my-key",
  location: "local", // שמירת מילון זה מקומי בלבד
  content: {/* ... */},
};
```

- `typesDir`
- `mainDir`
- `configDir`
- `cacheDir`
- `outputFilesPatternWithPath`

```typescript fileName="intlayer.config.ts"

  },
  system: {
    dictionariesDir: ".intlayer/dictionary", // מופרד בבירור
  },
};
```

## הפרדת ספריות תוכן וקוד

Intlayer v8 מפרידה בין התצורה עבור קובצי הגדרת תוכן לבין התצורה עבור טרנספורמציית קוד. הדבר מאפשר מעקב וסריקה מדויקים יותר, ומשפר את ביצועי הבנייה.

בעבר, `contentDir` שימש הן למעקב אחר קובצי `.content.*` והן לסריקת קוד עבור קריאות `useIntlayer`. כעת:

- **`contentDir`**: ספציפי לקובצי הצהרת התוכן שלכם.
- **`codeDir`**: ספציפי לקוד האפליקציה שלכם הזקוק לטרנספורמציה (למשל, גיזום, אופטימיזציה).

**הגירה:**

אם הגדרתם בעבר את `contentDir`, Intlayer v8 תשתמש בו כברירת מחדל גם עבור `codeDir`, אך תרשום אזהרה בלוג. עליכם להגדיר במפורש את `codeDir` בתצורה שלכם.

**התנהגות v7:**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    contentDir: ["src", "@packages/design-system"], // שימש הן לתוכן והן לקוד
  },
};
```

**התנהגות v8:**

```typescript fileName="intlayer.config.ts"
export default {
  content: {
    contentDir: ["src/content", "@packages/design-system"], // מעקב אחר קובצי src/content/*.content.* ו-@packages/design-system/dist/*.content.* בלבד
    codeDir: ["src", "@packages/design-system"], // סריקה לטרנספורמציית קוד כאן וקובצי @packages/design-system/src/*.content.* בלבד
  },
};
```

## יצירת מפת אתר (v8.6.0)

Intlayer יוצרת כעת מפות אתר (sitemaps) באופן אוטומטי בהתבסס על השפות שלכם ומצב הניתוב. הדבר שימושי במיוחד לאופטימיזציית SEO בארכיטקטורות נתבים כגון TanStack Router:

```typescript fileName="src/routes/sitemap.xml.ts"
import { createFileRoute } from "@tanstack/react-router";
import { generateSitemap } from "intlayer";

export const Route = createFileRoute("/sitemap.xml")({
  server: {
    handlers: {
      GET: async () => {
        const sitemap = generateSitemap(
          [
            { path: "/", changefreq: "daily", priority: 1.0 },
            { path: "/about", changefreq: "monthly", priority: 0.8 },
          ],
          { siteUrl: "https://example.com" }
        );

        return new Response(sitemap, {
          headers: { "Content-Type": "application/xml" },
        });
      },
    },
  },
  };
});
```

## הערות הגירה מ-v7

### שינויי תצורה

- **המאפיין `live`**: המאפיין `live` במילונים הוסר. השתמשו ב-`importMode: 'fetch'` במקום זאת.
- **importMode**: המאפיין `build.importMode` בתצורה הוצא משימוש. השתמשו ב-`dictionary.importMode` במקום זאת.
- **`contentDir` ו-`codeDir`**: `contentDir` מיועד כעת ספציפית לקובצי תוכן. מאפיין `codeDir` חדש נוסף לטרנספורמציית קוד. אם `codeDir` אינו מוגדר, Intlayer תיסוג ל-`contentDir` ותרשום אזהרה בלוג.
- **אימות סכמה**: כדי להשתמש בתכונת ה-`schema` החדשה, ודאו ש-`zod` מותקן בפרויקט שלכם.
